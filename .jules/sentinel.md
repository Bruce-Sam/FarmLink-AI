## 2024-05-24 - [CRITICAL] Guarded State Transitions (TOCTOU)
**Vulnerability:** A Time-of-Check to Time-of-Use (TOCTOU) vulnerability was found in the offer state transitions (`cancelOffer`, `rejectOffer`). The application read an offer to check if it was `PENDING`, and then later performed a blind `update` on the offer status. Concurrently, `acceptOffer` could successfully mark it as `ACCEPTED` and create a transaction, locking inventory. The blind update would then overwrite the status to `CANCELLED` or `REJECTED`, permanently locking inventory and orphaning the transaction.
**Learning:** Checking state before mutation is not enough in concurrent environments. If the state machine enforces terminal states or exclusive transitions, the update itself must be guarded to ensure atomicity.
**Prevention:** Always use `updateMany` with a `status` guard (e.g., `where: { id, status: EXPECTED_STATUS }`) when mutating state variables in a concurrent environment, checking `result.count > 0` before proceeding.

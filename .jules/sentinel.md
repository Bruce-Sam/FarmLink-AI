## 2025-09-29 - Default Admin Password in Production
**Vulnerability:** The application used `zod` to set a default value of `AdminPassword123!` for `ADMIN_PASSWORD` but failed to verify if this default password remained unchanged when starting in a production environment. This allowed the possibility of the backend starting in a temporary, but highly insecure state where an attacker could compromise the system using the known default credentials.
**Learning:** Default values for critical secrets are useful for local development and testing, but they pose a severe risk if accidentally deployed to production without overriding them. Validation guards that check against known default states must execute as early as possible during the application lifecycle, even before logging or database connections.
**Prevention:** Added a guard in `src/config/env.ts` to strictly throw an Error if `NODE_ENV=production` and `ADMIN_PASSWORD` equals `AdminPassword123!`. Also added unit tests utilizing `vi.resetModules()` to ensure the behavior across multiple test scenarios (`test`, `development`, `production`).

## 2026-09-19 - [CRITICAL] Prevent Default Admin Password in Production
**Vulnerability:** The configuration schema defined a default `ADMIN_PASSWORD` ('AdminPassword123!') without validating that it was changed in production. This risks unauthorized administrative access if an instance is deployed without explicitly overriding the default password in the environment variables.
**Learning:** Default fallback values for critical secrets can inadvertently become production credentials if not actively guarded against. Configuration validation (e.g. zod schemas) provides basic type safety, but environment-specific logic (like rejecting specific default values in production) must be explicitly enforced after parsing.
**Prevention:** Implement validation checks early in the application lifecycle (e.g., in configuration initialization) that explicitly fail fast if the application environment is production and critical secrets like the admin password match their unsafe default values. Ensure regression tests exist to prevent removal of these checks while continuing to allow defaults in development and test environments.

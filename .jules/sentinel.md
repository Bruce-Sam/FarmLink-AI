## 2025-02-28 - Reject Default Administrator Passwords in Production
**Vulnerability:** The application was using a default, hardcoded administrator password (`AdminPassword123!`) which would be implicitly loaded into production environments if the environment variable `ADMIN_PASSWORD` wasn't explicitly set. This could allow unauthorized access to the admin panel with a known credential.
**Learning:** Security configuration checks, such as validating production secrets or default passwords, must occur as early as possible in the application lifecycle (e.g., during environment variable validation) to prevent the system from entering an insecure state. Using `zod` default values can be dangerous for production if not accompanied by post-validation checks.
**Prevention:** Implement post-validation checks on configuration objects to explicitly fail fast (throw an error) when `NODE_ENV === 'production'` and secrets match known default values. Always write unit tests covering configuration instantiation across development, test, and production environments, remembering to use `vi.resetModules()` in Vitest to re-evaluate the config module.

## 2024-03-24 - Validate all default secrets in production early
**Vulnerability:** The application was rejecting the default `JWT_ACCESS_SECRET` in production, but was silently accepting the default `ADMIN_PASSWORD` (`AdminPassword123!`). This could lead to a critical vulnerability where an attacker uses default credentials to gain administrative access in production if the maintainer forgot to change the default value.
**Learning:** Security configuration checks must occur early in the application lifecycle. Hardcoded defaults used for local development must be explicitly validated and rejected when `NODE_ENV=production`. We cannot assume maintainers will change defaults; the app must fail to start if it detects dangerous defaults.
**Prevention:** Implement strict top-level environment configuration validation (e.g. using `zod`) that actively throws errors if production secrets match known fallback/default strings. Write regression tests using `vi.resetModules()` to ensure these checks work in production but allow defaults in dev/test.
